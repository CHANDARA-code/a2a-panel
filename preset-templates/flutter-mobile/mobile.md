## Versions
- Use the package versions in `pubspec.yaml` and `pubspec.lock`, and read that version's documentation before using an API: Riverpod, Freezed and go_router changed their APIs across major versions. For a new project use the current stable versions (check pub.dev; in October 2026: flutter_riverpod 3, riverpod_generator 4, freezed 3 or later, go_router 18, dio 5).

## Stack
- Flutter stable with Material 3.
- State: Riverpod with `riverpod_generator`. No `setState` beyond local UI state.
- Navigation: go_router with typed routes generated by `go_router_builder`.
- Networking: Dio with an interceptor for auth and error mapping; repositories return domain models, never raw JSON.
- Feature-first layout: `lib/features/<feature>/{data,domain,presentation}`.
- User-facing text comes from ARB files (`intl`); no hard-coded strings.

## Pitfalls
- After changing `@riverpod`, `@freezed`, `@JsonSerializable` or typed-route code, run `dart run build_runner build --delete-conflicting-outputs`. Never edit `*.g.dart` or `*.freezed.dart` files by hand.
- Freezed 3 and later: a Freezed class must be `abstract` or `sealed` (`sealed class Order with _$Order`) or implement `_$Order` itself, and `.when()` and `.map()` are gone; use Dart `switch` pattern matching instead.
- After an `await`, check `context.mounted` (or `mounted` inside a `State`) before using the `BuildContext`.
- Dispose what you create: `TextEditingController`, `AnimationController`, `ScrollController`, stream subscriptions.
